Épreuve E5 — Projet 2

Active Directory & Wi-Fi 802.1X Réalisé

SimCorp Solutions, PME fictive de 40 employés, souhaite centraliser l'authentification de ses utilisateurs et sécuriser l'accès à son réseau sans-fil. Le projet s'appuie sur l'infrastructure du Projet 1 (pare-feu, switch, Proxmox, Rsyslog) et y ajoute un contrôleur de domaine Windows Server et des bornes Wi-Fi Cisco en 802.1X.

Problématique

Avant le projet

  • Aucune gestion centralisée des utilisateurs : chaque poste utilisait un compte local
  • Accès Wi-Fi non contrôlé : une simple clé WPA2 partagée suffisait à se connecter
  • Aucune politique de sécurité uniforme : pas de verrouillage de session, pas de politique de mot de passe
  • Aucune traçabilité : impossible de savoir qui s'est connecté au réseau Wi-Fi

Architecture technique

Ce qui a été mis en place

SRV-AD-01 — Windows Server 2025

  • Active Directory DS + DNS + DHCP
  • NPS (serveur RADIUS intégré)
  • Domaine simcorp.local — IP fixe 172.16.213.10

Bornes Wi-Fi Cisco

  • Mode 802.1X — EAP-PEAP
  • Rôle d'authenticator
  • Relaient les requêtes vers le NPS

Stormshield — nouvelles règles

  • Interfaces VLAN 2091 et 2093 ajoutées
  • DHCP pour VLAN 2091 et 2093
  • Filtrage inter-VLAN (isolation Wi-Fi)

Switch Cisco CBS220 — mis à jour

  • VLAN 2091 (Wi-Fi) ajouté
  • VLAN 2093 (Serveurs) ajouté
  • Trunk mis à jour

Fonctionnement

Flux d'authentification 802.1X

  1. Le client Wi-Fi demande l'accès au réseau sans-fil.
  2. La borne Cisco bloque le trafic et demande des identifiants (EAP-PEAP).
  3. La borne relaye les identifiants vers le serveur NPS (RADIUS) — UDP 1812.
  4. Le NPS interroge l'Active Directory : le compte existe-t-il ? Est-il dans le groupe GRP_WiFi-Autorises ?
  5. Accès accordé (IP dans le VLAN 2091) ou connexion rejetée.

Chaque connexion est nominative, journalisée dans le Rsyslog et révocable en désactivant simplement le compte AD.
